# AI Photo Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The seller drops 20–60 photos, Claude groups them by what is in them and writes Hebrew copy for each group, and a review screen lets the seller correct clustering per photo and set price, dates and category across many items at once.

**Architecture:** Photo storage stops being keyed by item, which is what makes both automatic clustering and manual photo-moving cheap. Photos upload with a batch id and no item; one Claude call clusters them; one call per cluster writes the copy; DRAFT items are created and reviewed on a dedicated screen before publishing.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript strict, Prisma 6 + Postgres, sharp, `@anthropic-ai/sdk`, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-07-ai-import-design.md` — read it first; it is the authority this plan argues from.

## Global Constraints

- Hebrew for every user-facing string. No English in the UI.
- RTL: **CSS logical properties only**. In `dir="rtl"`, `inline-start` is the RIGHT physical edge. Never `left`/`right`.
- Any number range shown to a user (`12–18`, `09:00–12:00`) must be direction-isolated — `<Range>` for dates, `dir="ltr"` for hours. Bare, the bidi algorithm reverses it.
- Money is integer agorot everywhere. Never floats.
- `vitest.config.ts` keeps `fileParallelism: false`. Database tests share one Postgres and truncate in `beforeEach`; parallel files destroy each other. No task may remove it.
- Component tests opt into jsdom with a `// @vitest-environment jsdom` docblock. The global environment stays `node` — Prisma cannot run under jsdom.
- Photo cap: `MAX_PHOTOS_PER_ITEM` (10) binds `/api/upload` and `PhotoDrop` only. A **cluster has no cap**; the batch cap of 60 is the only bound on the import path.
- `ANTHROPIC_API_KEY` is optional. Its absence disables the feature; it must never stop the app booting and must never be added to `src/instrumentation.ts`'s required list.
- The AI SDK is called only from `src/lib/ai/`. No route, action or component imports it directly.
- Every task ends green: `npm run typecheck && npm test` before commit.

- [ ] **Step 3: Implement**

```ts
/**
 * Turns a model's grouping of photo indices into groups of photo ids, and
 * guarantees the accounting: every photo lands in exactly one group.
 *
 * A model can repeat an index, invent one, or quietly omit one, and none of
 * those may cost the seller a photo or duplicate it across two products.
 * Returns null only when the shape itself is wrong, which is the caller's
 * signal to fall back to capture-time grouping.
 */
export function normalizeClusters(raw: unknown, photoIds: string[]): string[][] | null {
  if (!Array.isArray(raw)) return null
  const groups: string[][] = []
  const seen = new Set<number>()

  for (const group of raw) {
    if (!Array.isArray(group)) return null
    const out: string[] = []
    for (const index of group) {
      if (typeof index !== 'number' || !Number.isInteger(index)) return null
      if (index < 0 || index >= photoIds.length) continue
      if (seen.has(index)) continue
      seen.add(index)
      out.push(photoIds[index])
    }
    if (out.length > 0) groups.push(out)
  }

  photoIds.forEach((id, index) => {
    if (!seen.has(index)) groups.push([id])
  })

  return groups
}
```

function classify(err: unknown): AiFailure {
  const status = (err as { status?: number })?.status
  const message = String((err as { message?: string })?.message ?? '').toLowerCase()

  return 'FAILED'
}

## Task 8: Photo move/remove, bulk edit, publish, discard

**Files:**
- Modify: `src/app/admin/items/import/actions.ts`
- Test: `tests/db/import-actions.test.ts`

**Interfaces:**
- Produces:
  ```ts
  movePhoto(photoId: string, toItemId: string | 'new'): Promise<{ok:true;itemId:string}|{ok:false;error:string}>
  removePhoto(photoId: string): Promise<{ok:true}|{ok:false;error:string}>
  bulkEdit(itemIds: string[], patch: {price?: string; categoryName?: string; pickupFrom?: string; pickupTo?: string}): Promise<{ok:true}|{ok:false;error:string}>
  publishItems(itemIds: string[]): Promise<{ok:true;published:number;refused:{id:string;error:string}[]}>
  discardItems(itemIds: string[]): Promise<{ok:true}>
  discardBatch(batchId: string): Promise<{ok:true;items:number;photos:number}>
  ```

`discardBatch` exists because `discardItems` is keyed by item and cannot reach
a photo that never got one. Between `/api/import` writing photos and
`clusterBatch` attaching them, a photo belongs to no item; a hard failure or a
closed tab in that window leaves rows and files nothing item-keyed can find.
